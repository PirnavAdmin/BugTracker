Pirnav Bug Tracking User Manual

Role-based guide for Admin, Tester, Developer, Lead, and Manager users.

Product: Pirnav Bug Tracking
Document: User Manual
Audience: Admin, Tester, Developer, Lead, Manager
Version: 1.0

1. Getting Started

  1. Open the application URL provided by your organization.
  2. Sign in with your registered email address and password.
  3. Use the top navigation bar to access Dashboard, Projects, Backlog, Stories, Tasks, Bugs, Reports, Team Activity, and Chat.
  4. Open your profile menu from the top-right avatar to manage profile, account, and help options.

2. Common Navigation

Area Purpose
Dashboard View high-level project, task, bug, and activity status.
Projects Create, review, and manage project records based on your permissions.
Backlog Plan upcoming work and organize pending items.
Stories Track user stories, requirements, and related work items.
Tasks Create, assign, update, and monitor implementation tasks.
Bugs Report defects, update bug details, attach evidence, and track fixes.
Reports Review project, team, task, and bug reporting views.
Team Activity Monitor team-level work progress and recent updates.
Chat Communicate with team members and share work-related updates.

3. Role Guide

Admin

  • Manage users, roles, teams, and workspace-level settings.
  • Create and maintain projects, assign members, and review account status.
  • Use reports to monitor organization-wide progress and bottlenecks.
  • Keep user access current by updating inactive users and role changes promptly.

Tester

  • Create bug reports with clear titles, steps to reproduce, expected result, actual result, severity, priority, and attachments.
  • Track assigned bugs and update testing status after verification.
  • Add screenshots, logs, or other evidence when reporting or retesting a defect.
  • Move verified fixes to the appropriate resolved or closed status based on team workflow.

Developer

  • Review assigned tasks and bugs from the Tasks and Bugs sections.
  • Update status, estimates, comments, and implementation notes as work progresses.
  • Use bug details to understand reproduction steps and attached evidence before starting a fix.
  • Notify testers or leads when a fix is ready for verification.

Lead

  • Plan work across backlog, stories, tasks, and bugs.
  • Assign items to developers and testers based on priority and availability.
  • Review team activity to identify blocked work and overdue items.
  • Use reports to prepare status updates and guide daily execution.

Manager

  • Monitor project health, delivery progress, open bugs, and team workload.
  • Use reporting pages to understand trends, risks, and completion status.
  • Review high-priority bugs and overdue tasks during planning and review meetings.
  • Coordinate with leads and admins when project scope, staffing, or access needs change.

4. Bug Reporting Workflow

  1. Open the Bugs section and choose the option to create or report a bug.
  2. Enter a specific title that describes the issue clearly.
  3. Select the related project, priority, severity, assignee, and status where applicable.
  4. Describe steps to reproduce, expected result, actual result, environment, and any dependency information.
  5. Attach supporting files such as screenshots, logs, documents, or videos if available.
  6. Submit the bug and monitor comments or status updates until it is verified and closed.

5. Task And Story Workflow

  1. Create stories or tasks with enough detail for the assigned team member to begin work.
  2. Set assignee, project, priority, due date, dependency, and status fields accurately.
  3. Update progress regularly so reports and team activity remain reliable.
  4. Use comments and attachments to keep discussions close to the work item.

6. Profile And Account

  • Open Profile from the top-right user menu to view account information.
  • Use Change Password to update your password regularly.
  • Use Documentation to download this manual for offline reference.
  • Contact your administrator or support contact when your role, team, or access appears incorrect.

7. Good Practices

  • Keep titles short, specific, and searchable.
  • Record decisions and clarifications in comments on the related item.
  • Attach evidence for bugs and important delivery risks.
  • Update status as soon as work moves forward, gets blocked, or is completed.
  • Review reports before team meetings so blockers can be addressed quickly.

This manual is intended as a general guide. Your organization may apply additional workflow rules based on project, team, or customer needs.
